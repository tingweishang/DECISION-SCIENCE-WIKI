作業說明

流程與驗證

Loop / Graph

  1. A　取得原始資料｜依原對話的主題與教學範圍，取出六份附件並保留雜湊。
  2. B　逐頁擷取與檢查｜保留實體頁序，檢查文件數、頁數與文字。若檔案或頁序有誤，回 A。若公式缺字，回 PDF 原頁影像。
  3. C　編寫與核對 Wiki｜整理定義、條件與公式，登記講義與頁碼。一旦查不到依據，回 B 找原頁並改寫。
  4. D　查詢 Wiki，生成教學內容｜選定知識條目，設計案例和互動題。計算或引用有問題時，回 C 或改寫 D。
  5. E　驗證並交付｜檢查連結、空查詢、公式、頁面互動。失敗時修正受影響的節點，再跑同一組驗證。

回圈　B → 原頁影像 → B　｜　C → B → C　｜　E → C 或 D → E

文件頁序、公式完整性和引用先檢查，避免錯誤寫進 Wiki 後再傳到多頁簡報。互動程式則在產出後檢查，因為使用者操作才會觸發部分狀態。

反思

這次實跑中，擷取與來源核對節點出現兩件問題。第一次讀取擷取結果時，擷取程序尚未結束，JSON 為空。等待程序結束後再跑，成功讀到 100 頁。另一件是 Lecture 4 第 11 頁的相關係數分母在文字擷取時遺失。回查原頁影像後，Wiki 公式補上 σₓσᵧ。

因此把檢查移到擷取與寫入 Wiki 之間。先確認擷取結束與頁序，再比對公式影像。流程也增加了「公式缺字 → 回查原頁 → 核對後才入 Wiki」的回路。瀏覽器測試另發現清除篩選後顯示舊結果，修正後以同一組搜尋與篩選步驟重試，恢復 17 則條目。

GitHub Pages

將 docs 資料夾放在 GitHub repository 的 main 分支。到 Settings → Pages，選 Deploy from a branch，再選 main 和 /docs 後儲存。部署完成後，用 Pages 顯示的網址開啟 Wiki，並點進簡報測試操作及來源連結。
